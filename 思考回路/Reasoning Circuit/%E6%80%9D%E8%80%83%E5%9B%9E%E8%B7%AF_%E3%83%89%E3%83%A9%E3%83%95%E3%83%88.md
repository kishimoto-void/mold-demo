# 汎用型思考回路 — Draft

- **文書状態:** Draft / 骨格優先
- **版:** 0.1
- **目的:** 分野ごとの知識や計算式を差し替えながら、問題を分解・接続・変換・検証・収束させる汎用プロセスの骨格を定義する。
- **注意:** 本文の数式は、既存理論を参考に構成した設計用の仮説モデルである。実証済みの単一公式を提示するものではない。

---

## 1. 基本構想

思考を単発の回答生成としてではなく、**状態が更新され、要素間を影響が伝播し、結果が再評価される回路**として扱う。

基本ループ：

`INPUT → MATERIAL → SCALE → DRIFT → ≌C → HYPOTHESIS → DIFFUSION → CONVERGENCE`

必要に応じて、`CONVERGENCE` から `MATERIAL`、`DRIFT`、`≌C` などへ戻り、再処理する。

### 設計原則

1. **分解:** 問題・要素・条件・未知情報を分ける。
2. **接続:** 要素間の依存・因果候補・相互作用を記録する。
3. **変換:** 元の情報を保ちつつ、仮説や表現を変える。
4. **比較:** 一致だけでなく、差分・矛盾・未確定部分も記録する。
5. **伝播:** 一要素の変化が周辺要素へ与える影響を追う。
6. **収束:** 目的・制約・根拠に照らして結果をまとめる。
7. **再帰:** 新しい結果を次の状態の入力として使う。
8. **未知の保持:** 根拠が不足する箇所を、無理に確定させない。

## 2. 基本記号

| 記号 | 意味 |
|---|---|
| `I` | INPUT：問題、要求、観測、資料 |
| `X_t` | STATE：時点 `t` の理解状態 |
| `G` | GRAPH：要素・依存・影響の接続構造 |
| `H` | CONSTRAINT：目的、制約、禁止事項、評価基準 |
| `Φ` | CIRCUIT：状態を更新する処理全体 |
| `Ω` | 比較・評価の観点 |
| `ε` | 比較上の許容差・停止閾値（適用可能な場合） |
| `D` | Diffusion：伝播・展開・増幅を扱う処理 |
| `C` | Contraction：絞り込み・抑制・減衰を扱う処理 |
| `R_t` | Residual：残差、差分、矛盾、未解決項目 |

### 2.1 `≌` の暫定定義

この設計書では `≌` を、**異なる状態・表現の間に、指定された観点と条件のもとで近似的な対応関係が成立すること**を表す独自記号として使用する。

- `≌` は、完全一致や同一性を意味しない。
- 対応を認める観点 `Ω` と、必要に応じて許容差 `ε` を明示する。
- 標準数学での記号の用法とは区別し、プロジェクト内の演算規約として定義する。
- 数値比較ができない意味情報では、数値誤差ではなく、根拠・条件・関係性に基づいて対応を判定する。

暫定表記：

`A ≌_(Ω, ε) B`

意味：`A` と `B` は、観点 `Ω` および条件 `ε` に照らして対応すると判定された。

## 3. 中核となる状態更新式

### 3.1 汎用式

`X_(t+1) ≌_(Ω, ε) Φ(X_t, I, G, H)`

意味：現在の状態 `X_t` を、入力 `I`、接続構造 `G`、制約 `H` に基づく処理 `Φ` で更新し、判定基準 `Ω` のもとで次状態との対応を評価する。

より厳密に運用する場合は、更新処理と対応判定を分ける：

1. `X*_(t+1) = Φ(X_t, I, G, H)`
2. `Match = ≌_(Ω, ε)(X*_(t+1), X_(t+1))`

`X*` は処理によって提案された次状態、`X` は採用・検証された次状態を表す。

### 3.2 処理全体の合成

`Φ = CONVERGENCE ∘ DIFFUSION ∘ HYPOTHESIS ∘ ≌C ∘ DRIFT ∘ SCALE ∘ MATERIAL`

関数合成は右側から順に適用する。

これは基本の処理順序を示す。実際の回路では、エラーや未確定事項に応じて一部工程へ戻る分岐を許可する。

## 4. モジュール骨格

### 4.1 INPUT

**役割:** 問題、目標、質問、観測、資料を受け取る。

**出力:** `I`、入力条件、情報源、入力時点。

### 4.2 MATERIAL

**役割:** 入力を要素・事実・仮定・制約・未知情報へ分解する。

**出力:** 要素集合、事実／仮定の区別、未確認項目。

### 4.3 SCALE

**役割:** 重要度、影響範囲、時間尺度、優先順位を整理する。

**出力:** 優先度、分析単位、対象範囲。

### 4.4 DRIFT

**役割:** 別解釈、代替仮説、視点変更、派生可能性を探索する。

**出力:** 仮説候補、代替モデル、前提変更の記録。

### 4.5 ≌C — Correspondence Check

**役割:** 情報・状態・仮説の対応を比較し、一致・差分・矛盾・不明を分ける。

**出力:** 対応判定、差分 `R_t`、根拠、判定条件 `Ω`。

`≌C` は暫定名称。`C` は比較・対応確認を示し、収縮演算 `Contraction` とは区別する。

### 4.6 HYPOTHESIS

**役割:** 観測、対応関係、差分をもとに、説明・予測・解決案を構成する。

**出力:** 仮説、前提、確信度または不確実性、検証方法。

### 4.7 DIFFUSION

**役割:** ある要素や仮説の変化が、接続先へどう伝わるかを探索・計算する。

**出力:** 影響先、伝播経路、増幅・減衰候補、二次影響。

### 4.8 CONVERGENCE

**役割:** 目的・制約・根拠に照らして情報を統合し、回答または暫定結論を作る。

**出力:** 結論、根拠、未解決事項、次の処理先。

## 5. 連環・拡散・収縮・エコー

### 5.1 連環

一つの要素の状態変化が別の要素へ影響し、その結果がさらに次の状態を変える構造を **連環** と呼ぶ。

`X_A → X_B → X_C → ...`

フィードバックがある場合：

`X_A → X_B → X_C → X_A'`

`X_A'` は、周辺の結果を受けて更新された `X_A` の状態を表す。

### 5.2 拡散と収縮

概念上の分解：

`STATE CHANGE ≌ DIFFUSION − CONTRACTION`

数値ベクトルとして表現でき、各作用が同じ空間で定義されている場合は、次のようなモデルを採用できる。

`ΔX_t = D_G(X_t) − C_H(X_t)`

- `D_G`: 接続構造 `G` に沿った伝播・拡大・増幅
- `C_H`: 制約 `H` による抑制・絞り込み・減衰

**注意:** 意味・文章・仮説など、直接減算できない情報にこの式を機械的に適用しない。その場合は、拡散と収縮を別個の変換操作として実装する。

### 5.3 エコー

伝播後に得た影響・観測・反応を、元の状態または別の関連状態へ返すフィードバック。

`X_(t+1) = Φ(X_t, I, G, H, Echo_t)`

エコーは単なる繰り返しではなく、前回の処理で生じた差分を使って状態を更新する。

### 5.4 連環の停止・遮断

- 接続がない場合、影響経路を仮定しない。
- 根拠がない派生関係は「未確認」とする。
- 制約や耐性が影響を止める可能性を扱う。
- フィードバックが発散する場合は、反復回数・影響範囲・更新量に上限を設ける。

## 6. 収束と停止条件

暫定的な停止条件：

`STOP ⇔ VALID(X_(t+1), H) ∧ STABLE(X_(t+1), X_t) ∧ BUDGET_OK`

- `VALID`: 必要な制約・根拠要件を満たす。
- `STABLE`: 状態変化が指定条件のもとで十分に小さい、または目的を満たす。
- `BUDGET_OK`: 許容反復数・時間・計算資源などの上限に達していない。

数値化できる場合の一例：

`d_Ω(X_(t+1), X_t) ≤ ε`

ただし、**変化が小さいことだけで正しさを保証しない**。妥当性検証、情報不足、反復上限を別々に扱う。

停止結果は、少なくとも次のいずれかに分類する。

- `CONVERGED`: 制約を満たし、結論がまとまった。
- `PARTIAL`: 一部のみ確定できた。
- `UNRESOLVED`: 根拠不足などで未解決。
- `LIMIT_REACHED`: 反復・資源上限に到達した。
- `CONFLICT`: 解消されていない矛盾が残る。

## 7. 適用イメージ

### 7.1 地震・設備被害

`震源・地震動 → 設備状態 → 一次被害 → 依存先の派生被害 → フィードバック`

- 入力: 地震動・発生条件
- ノード: 発電所、工場、交通、通信など
- 接続: 電力・物流・制御・供給の依存関係
- 制約／耐性: 設備設計、安全機構、管理状態、代替経路
- 拡散: 停止・故障が依存先へ波及
- 収縮: 隔離、冗長化、停止機構、復旧

被害を震源規模だけから決定せず、各ノードの状態と依存関係を介して評価する。

### 7.2 企業・市場リスク

`広報問題／品質問題 → ブランド評価 → 消費者行動 → 売上見通し → 取引先・市場評価`

これは検証対象となる仮説経路であり、各矢印が必ず成立するとは限らない。供給関係や取引依存度など、実際の接続を確認してから波及を推定する。

### 7.3 汎用思考

`問題 → 要素分解 → 関係構造 → 仮説 → 伝播・反証 → 統合結論`

ドメインごとに、要素の種類、接続規則、評価関数、制約、検証方法を差し替える。

## 8. 実装時の境界

この思考回路は、基盤LLM自体を置き換えるものではなく、**LLMや各種ツールの処理を構造化する上位プロセス**として設計する。

モジュール間で最低限受け渡す情報：

- `input`: 元の依頼・観測
- `state`: 現在の状態
- `elements`: 分解された要素
- `relations`: 接続・依存関係
- `assumptions`: 仮定
- `evidence`: 根拠・情報源
- `residuals`: 差分・矛盾・未解決事項
- `hypotheses`: 仮説候補
- `constraints`: 目的・制約
- `status`: 処理状態
- `next_action`: 次の処理先

**重要:** 推論過程を無制限に文章化することより、状態・根拠・差分・次の処理を記録し、再検証できることを優先する。

## 9. 未確定事項・次の設計課題

1. `≌` の形式的定義、適用範囲、判定結果の型を確定する。
2. `≌C` の出力形式（一致／近似対応／差分／矛盾／不明）を定義する。
3. `G` の表現方式（有向グラフ、重み、時間依存、循環）を決める。
4. 数値系と意味情報系で、拡散・収縮をどう別実装にするか決める。
5. 仮説の根拠、不確実性、反証条件を保持する。
6. 収束・停止・再試行の条件と上限を定める。
7. 小さなテストケースで、伝播が止まるケース・増幅するケース・未解決を保持するケースを検証する。

## 10. 現時点の最小定義

> **汎用型思考回路とは、入力を構造化し、要素間の関係を組み立て、対応・差分を判定し、仮説を生成・伝播させ、制約に照らして状態を更新する反復プロセスである。**

中核式：

`X_(t+1) ≌_(Ω, ε) Φ(X_t, I, G, H)`

中核フロー：

`INPUT → MATERIAL → SCALE → DRIFT → ≌C → HYPOTHESIS → DIFFUSION → CONVERGENCE ↺`

この文書では骨格のみを固定し、係数・詳細アルゴリズム・ドメイン別ルールは次段階で定義する。
